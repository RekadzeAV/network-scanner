# Security Policy

## Поддерживаемые версии

| Версия | Поддержка |
|--------|-----------|
| 2.3.x | ✅ активно |
| < 2.3 | ❌ не поддерживается (обновитесь до последнего релиза) |

## Сообщение об уязвимости

Если вы обнаружили уязвимость, **не открывайте публичный issue**.

1. Используйте [GitHub Private Vulnerability Reporting](https://github.com/RekadzeAV/network-scanner/security/advisories/new)
   (Settings → Security → Private vulnerability reporting).
2. Если отчёт недоступен, напишите владельцу репозитория (@RekadzeAV) через
   GitHub с пометкой `[SECURITY]` в теме.

В отчёте укажите:

- версию и платформу (`network-scanner version`);
- шаги воспроизведения;
- ожидаемое и фактическое поведение;
- потенциальное влияние.

## Сроки реакции

| Этап | Срок |
|------|------|
| Подтверждение получения | 3 рабочих дня |
| Оценка критичности | 7 рабочих дней |
| Исправление критичных уязвимостей | 30 дней |
| Публикация advisory + релиз с патчем | вместе с ближайшим релизом |

## Область (Scope)

В область входит код этого репозитория: CLI, GUI, API-сервер, remote-exec,
device-control, плагины.

Вне области:

- уязвимости сторонних зависимостей (сообщайте upstream, продублируйте сюда);
- проблемы сетей/оборудования, на которых запускается сканер;
- использование инструмента внеauthorized сетей (см. DISCLAIMER в README).

## Best practices для пользователей

- Запускайте сканирование только в сетях, где у вас есть разрешение.
- Для ARP/ICMP используйте `setcap cap_net_raw+ep` вместо запуска от root.
- API-сервер слушайте на loopback (`127.0.0.1`) либо включайте Bearer-аутентификацию.
- Remote-exec работает в dry-run по умолчании; включайте `--execute` осознанно.
- Секреты (community strings, токены) не передавайте через аргументы командной
  строки — используйте файлы с правами 0600.
