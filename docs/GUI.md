# GUI версия - Графический интерфейс

**Дата обновления:** 2026-10-14  
**Текущая версия:** v2.3.0

## Описание

GUI версия Network Scanner предоставляет графический интерфейс пользователя для сканирования локальной сети с использованием фреймворка Fyne (v2.7.1).

## Компоненты

### internal/gui/app.go

Содержит основной класс `App`, который управляет:

- **Окном приложения** - создание и настройка главного окна
- **UI компонентами** - поля ввода, кнопки, метки, прогресс-бар
- **Обработкой событий** - реакции на действия пользователя
- **Процессом сканирования** - запуск и управление сканированием
- **Сохранением результатов** - экспорт результатов в файл

#### Основные методы:

- `NewApp()` - создание нового экземпляра GUI приложения
- `initUI()` - инициализация всех элементов интерфейса
- `setupEventHandlers()` - настройка обработчиков событий
- `startScan()` - запуск процесса сканирования сети
- `saveResults()` - сохранение результатов в файл
- `Run()` - запуск GUI приложения

### cmd/gui/main.go

Точка входа GUI приложения. Содержит минимальный код для запуска:

```go
func main() {
    app := gui.NewApp()
    app.Run()
}
```

## Использование

### Сборка

```bash
go build -o network-scanner-gui ./cmd/gui
```

Релизный скрипт **`./scripts/build-gui-release.sh`** сохраняет GUI-бинарники в **`build/release/<YYYY-MM-DD-N>/`** в корне репозитория. Для запуска на macOS используйте `./scripts/build-gui-release.sh && ./build/release/<YYYY-MM-DD-N>/gui-darwin-universal`. Подробнее: [BUILD_STRUCTURE.md](BUILD_STRUCTURE.md).

> **Примечание:** `launch-gui.sh` [ARCHIVED] — устаревший скрипт, перемещён в `internal/legacy/`. Используйте `scripts/build-gui-release.sh`.

### Запуск

```bash
./network-scanner-gui
```

### Возможности

- **Автоматическое определение сети** - если поле сети оставлено пустым, приложение автоматически определяет локальную сеть
- **Ручной ввод сети** - можно указать сеть вручную в формате CIDR (например, 192.168.1.0/24)
- **Индикация прогресса** - прогресс-бар показывает ход сканирования
- **Отображение результатов** - режимы `Таблица`/`Карточки`, сортировка и фильтры
- **Подрежимы результатов** - `Устройства` / `Безопасность` / `Инвентарь` на вкладке `Сканирование` (P2-7)
- **Сохранение результатов** - возможность сохранить результаты сканирования в текстовый файл
- **Инструменты** - `Ping`, `Traceroute`, `DNS`, `Whois`, `Wi-Fi`, `Wake-on-LAN`, `Аудит портов`, `Risk Signatures`, `Device Control`, сгруппированы в карточки-категории: «Сетевые утилиты», «Wake-on-LAN», «Управление устройством (HTTP API)», «Аудит и риски»
- **Operations Center** - история операций инструментов с действиями `Retry`/`Cancel`
- **Host Details Drawer** - панель деталей выбранного хоста + быстрые действия (`Ping`/`Traceroute`/`DNS`/`Whois`/`WOL`)
- **Группировка панели сканирования** - «Основное» (сеть/порты/запуск) всегда видимо; пресеты, автопрофиль, таймаут/потоки и опции UDP/баннеры/ОС — в сворачиваемых секциях `widget.Accordion`
- **Валидация ввода on-the-fly** - CIDR и диапазон портов проверяются при вводе; ошибка показывается под полем (цвет ошибки темы)
- **Секционирование панели топологии** - боковая панель разбита на карточки: «Подключение (SNMP)», «Отчёты и превью», «Интерактивная карта»
- **Сворачиваемая панель фильтров результатов** - редкие настройки (режим отображения, сортировка, CIDR, пресеты, быстрые фильтры, Inventory DB) вынесены в Accordion «Фильтры и режимы отображения»; на виду остаются текстовый фильтр, счётчик фильтров и сброс. В подрежиме `Inventory` панель сворачивается автоматически
- **Статус-бар с уведомлениями** - единая точка обратной связи (`setStatus`); временные подтверждения показываются тостом с маркером «✓» и авто-возвратом через 4 секунды (`setStatusToast`); ошибки — с маркером «✗» (`setStatusErrorToast`, S-04)
- **Меню «Справка»** - «Горячие клавиши» (F1) и «О программе» (версия, ОС/арх, версия Go)
- **Интерактивная карта топологии** - выбор узлов и связей, фильтры (`query/type/confidence`) и click-through в `Host Details`
- **Диагностика сканирования** - копирование/сохранение diagnostics summary последнего запуска
- **Автопрофиль сканирования** - мягкая авто-коррекция heavy-настроек на больших подсетях (`ports/threads`)
- **Рекомендуемые настройки** - отдельная кнопка с безопасным one-click профилем и подсказкой `Почему?` по логике адаптации
- **Бейдж профиля** - строка `Профиль: ...` показывает текущий класс (`small/medium/large/very-large`), класс хранится отдельно в `Preferences` и восстанавливается после перезапуска (с fallback на legacy текст)

## Темизация

GUI использует единую систему темизации на основе токенов (WCAG AA):

- **`theme.go`** — `ModernTheme` (реализует `fyne.Theme`), вариант-зависимая палитра, `followSystem`
- **`theme_tokens.go`** — единый источник цветовых значений (light/dark), палитра состояний портов, токены топологии
- **`theme_selector.go`** — меню «Тема»/«Акцент», `applyThemeToUI()`, инвалидация кэшей
- **`accent_colors.go`** — 7 акцентных пресетов (macOS Blue, Windows 11, Green, Purple, Orange, Red, Teal) с подбором `OnPrimary` по контрасту

### Поддерживаемые темы
- Светлая (`light`)
- Тёмная (`dark`)
- Системная (`system`) — следует за вариантом ОС через `followSystem`

### Контраст
Все цвета проходят WCAG AA:
- Текст: ≥4.5:1 на поверхности своего варианта
- Нетекстовые элементы (рамки, чипы, графика): ≥3.0:1

## Технические детали

### Поток выполнения

1. Пользователь запускает приложение
2. Инициализируется GUI интерфейс
3. Пользователь может указать сеть или оставить поле пустым
4. При нажатии "Запустить сканирование":
   - Определяется сеть (автоматически или из поля ввода)
   - Создается экземпляр NetworkScanner
   - Запускается процесс сканирования в отдельной горутине
   - Обновляется прогресс-бар
   - По завершении результаты форматируются и отображаются
5. Пользователь может сохранить результаты в файл

### Обновление UI

Обновления UI выполняются в главном потоке Go для безопасности. Длительные операции (сканирование) выполняются в отдельных горутинах.

### Форматирование результатов

Для вкладки результатов используется комбинированный UI:
- подрежим `Devices` — таблица/карточки + Host Details Drawer + встроенная аналитика;
- подрежим `Security` — сводка findings (`audit` + `risk signatures`) и экспорт HTML отчета;
- подрежим `Inventory` — инвентаризация (SQLite) с diff снапшотов.

**Чипы портов** (R-05): семантический компонент с различимыми состояниями:
- `open` — маркер `●`, зелёная подложка (WCAG 1.4.1 — не только цвет);
- `closed` — без маркера, нейтральная подложка;
- `filtered` — маркер `◌`, жёлтая подложка;
- `unknown` — маркер `—`, нейтральная подложка.

**Таблица результатов**:
- заголовок закреплён над данными (`widget.Table.ShowHeaderRow`, R-01) и не скроллится вместе со строками;
- сортировка кликом по заголовку: индикатор `▲`/`▼` показывает режим и направление (R-03); сортируемые колонки — «Имя хоста», «IP», «Тип», «Порты (открытые)»; направление хранится в `scan.results_sort_asc`;
- технические колонки IP/MAC — моноширинный шрифт (T-04);
- категория устройства показана визуальным маркером вместо ASCII-тега (R-08): `⬡` сетевое устройство, `◎` точка доступа, `⎙` принтер, `◉` камера, `▤` NAS, `◈` IoT, `▢` компьютер, `▣` сервер, `▮` мобильное, `◌` неизвестно;
- счётчик строк в шапке области результатов: `Строк: N` или `Строк: показано X из Y` (R-09/R-12).

**Live-результаты** (R-04): во время сканирования (`scanning` state) публикуется снапшот результатов по порогу времени вместо «мёртвого» экрана.

**Состояния результатов** (N-09): область результатов имеет 5 состояний — `idle`, `scanning`, `done`, `stopped`, `timeout`. Подпись локализована (`resultsStateCaption`): «Ожидание сканирования», «Сканирование выполняется…», «Результаты получены: N устройств», «Сканирование остановлено», «Сканирование прервано по таймауту». Контроллер сообщает о переходах через `ScanActions.SetResultsState(state, found)` — технические значения констант в UI не показываются. Пустые/ошибочные состояния отображаются через `buildResultsEmptyState` (S-01).

**Прогресс-бар** (S-02): получает долю `0…1` (`SetValue(ev.Percent)`), подпись со счётчиком (`Current/Total`) и ETA.

Для больших выдач в `Devices` применяются оптимизации:
- debounce перерисовки для burst-ввода фильтров/поиска;
- virtualized cards через `widget.List` (рендерятся только видимые элементы);
- progressive load карточек кнопкой `Показать еще (...)`;
- cache/prefetch для `Host Details` по IP (ускоряет переключение между соседними хостами).

Для вкладки инструментов используется `RichText` с markdown-совместимым выводом и отдельный `Operations Center` для отслеживания выполнения и повторного запуска операций.

### Интерактивная карта топологии

**Узлы** (H-01): `tappableNode` — кастомный виджет (`widget.BaseWidget` + `desktop.Tappable` + `desktop.Hoverable`):
- курсор-указатель при наведении;
- hover-подсветка (увеличение обводки);
- hit-зона 28×28 лог. px (WCAG 2.5.8);
- клик выбирает узел и открывает Host Details.

**Связи** (H-02): невидимый `linkHitArea` 12px ширины вдоль линии + бейдж-кнопка:
- клик по hit-area или бейджу выбирает связь;
- подсветка выбранной связи токеном `tokTopoLinkHighlight`.

**Цвета карты** (H-03): все цвета из токенов `theme_tokens.go`:
- узлы по типу: `tokTopoNodeRouter`, `tokTopoNodeSwitch`, `tokTopoNodeHost`, `tokTopoNodeOther`;
- связи по уверенности: `tokTopoConfHigh`, `tokTopoConfMedium`, `tokTopoConfLow`;
- обводка выбранного узла: `tokTopoNodeBorderSelect` (контраст AA в обоих вариантах).

**Зум и панорама** (H-07): `topologyViewport` — слой ввода поверх холста карты.
- Колесо мыши → зум ±1.2×, диапазон 35%–300%;
- Drag → панорама с ограничением ±60% размера мира;
- Кнопки «+ / − / Сброс» в карточке «Интерактивная карта»;
- Scroll-контейнер с динамическим `SetMinSize(worldSize)` — скроллбары появляются при зуме >100%;
- Hit-зоны узлов/связей масштабируются с zoom (минимум WCAG 2.5.8: 14 px / 12 px).

**Слоистая раскладка** (H-08): три яруса сверху вниз вместо радиального круга.
- Ярус `core` (router) → `dist` (switch) → `host` (остальное);
- Строки внутри яруса центрируются, пустые строки не рисуются;
- `topologyComputeLayout` — детерминированный порядок узлов (сортировка по ключу).

### Адаптивность интерфейса (окно/полный экран)

GUI использует адаптивные профили ширины окна:
- `compact` (<= 1366 px): уплотненная компоновка, `Host Details` переходит в вертикальный split;
- `normal` (1367-2199 px): стандартная компоновка;
- `wide` (>= 2200 px): расширенные ширины таблиц и области результатов.

Поддерживаемая матрица проверок:
- Разрешения: `1366x768`, `1600x900`, `1920x1080`, `1920x1200`, `2560x1440`, `3440x1440`, `3840x2160`.
- Масштаб Windows (DPI): `100%`, `125%`, `150%`, `200%`.
- Режимы: оконный (минимальный/средний) и полноэкранный.

Критерии приемки UI:
- одинаковая доступность функций в оконном и полноэкранном режимах;
- отсутствие обрезки критичных контролов;
- корректное отображение вкладок `Сканирование`, `Топология`, `Инструменты` на `1366x768`.

Быстрая проверка матрицы:
- Windows: `scripts/smoke_release_readiness.ps1`
- Linux/macOS: `scripts/smoke_release_readiness.sh`

## Расширение

Для добавления новых функций в GUI:

1. Добавьте новые UI компоненты в метод `initUI()`
2. Добавьте обработчики событий в `setupEventHandlers()`
3. Реализуйте логику в соответствующих методах класса `App`

При необходимости можно создать дополнительные файлы в `internal/gui/` для разделения функциональности (например, отдельный файл для виджетов или для работы с настройками).
