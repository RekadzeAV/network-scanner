## 1. Резюме

GUI функционально насыщенный, но визуально и эргономически неконсистентный: три конкурирующих слоя темизации, из них один рабочий и два мёртвых; ~50 «сырых» цветовых литералов в коде рендера; контраст половины статусных цветов ниже WCAG AA; переключатель темы в меню не работает; HiDPI принудительно отключён; таблица результатов не даёт ни «прилипающего» заголовка, ни сортировки по клику, ни моноширинного выравнивания для IP/MAC.

### 1.2 Что предлагается (кратко)

1. **Один слой темизации** с токенами (P0-1…P0-4): удалить мёртвый слой, сделать тему вариант-зависимой, починить меню и «системный» режим.
2. **Палитра, удовлетворяющая WCAG AA** (P0-5, §5.2) — готовые значения с посчитанным контрастом.
3. **Вернуть HiDPI** (P0-6) и ввести **плотность** (comfortable/compact) вместо жёстких `Padding=12/Text=14`.
4. **Таблица как основной инструмент** (P1-1…P1-4): live-строки во время скана, фиксированный заголовок, сортировка по клику, моноширинные технические колонки, port-state семантика.
5. **Состояния и обратная связь** (P1-5…P1-7): статус-бар как единая «приборная панель», полноценные empty/error-состояния, осмысленный прогресс.
6. **Карточки-секции, иконки, hit-зоны, курсоры** (P2) — полировка.

## 2. Как устроена темизация сейчас (и почему это источник большинства дефектов)

```
 Слой 1 (РАБОЧИЙ)                Слой 2 (ЧАСТИЧНЫЙ)               Слой 3 (МЁРТВЫЙ)
 ModernTheme (theme.go)          рендер-цвета в коде              ThemeManager (theme_manager.go)
   isDark → lightColor/darkColor  chipBackground()/rowBackground()  GetTheme()/ToggleTheme()/
   Color() игнорирует variant     pieBg, piePalette,               RegisterThemeChanged()
   Size(): Padding 12, Text 14    canvas.NewText(#3CAA50…)         вызывается только из тестов
        │                                   │                              │
        └── App.applyTheme(mode) ───────────┘                              ✗ не подключён
            (theme_selector.go)   ↑
                                  └── setupMainMenu() (ui_helpers.go) — единственная точка
                                      применения темы; вызывается из Run()
```

Следствия, подтверждённые чтением:

* **≈50 цветовых литералов** живут вне темы и синхронизируются вручную через `currentThemeIsDark()` (`results_charts.go:26-39`). Правка палитры требует обхода 6+ файлов (полный перечень — Приложение B).
* `ModernTheme` переопределяет **21 из 28** `theme.ColorName*` v2.7.1. Не переопределены и уходят во `DefaultTheme()` с **фиксированным** вариантом: `Hyperlink`, `HeaderBackground`, `ScrollBarBackground`, `ForegroundOnPrimary/OnError/OnSuccess/OnWarning`. Итог — смесь собственной палитры и встроенной (например, тёмный `HeaderBackground` из коробки рядом с `#202020` окна).
* `ModernTheme.Variant()` (`theme.go:36-41`) не входит в интерфейс `fyne.Theme` (`Color/Font/Icon/Size`) — метод не читается фреймворком.
* Тема применяется один раз в `Run()` → `setupMainMenu()`; перерисовка «кодированных» цветов — через `scheduleResultsRender(true)` (`ui_helpers.go:104-108`). Виджеты, созданные до/вне этого пути, сохраняют старые цвета.

### 4.1 Выводы для нашего интерфейса

1. **Таблица — главная поверхность.** У всех аналогов постоянная «хрома» (панели, пресеты, диагностика) минимальна; у неё в окне до 8 строк хромы над таблицей + аккордеоны (`results_ui_sections.go:263-282`).
2. **Live-результат — стандарт индустрии.** Ни один аналог не показывает «просто текст» во время скана (F-09, R-04).
3. **Топология — представление результата, а не отдельная вкладка со своими настройками.** Zenmap держит SNMP-настройки в профиле скана, а топологию — как вкладку результата; у нас — отдельная вкладка с собственной панелью сверху (N-05).
4. **Детали хоста — несущая мастер-деталь**, а не карточка-«дополнение» (R-10).
5. **Статус-бар обязателен**: прогресс, счётчик, ETA, состояние сети — в одном постоянном месте (N-07).
6. **Колонки настраиваемые** — способ решить конфликт «256 хостов × 8 колонок × узкий экран» вместо трёх профилей макета с магическими числами.

### P0 — базовая корректность (без этого интерфейс «не работает»)

**P0-1. Один слой темизации: `AppTheme` + токены, удаление мёртвого кода**

*Проблема:* 3 слоя (§2), два из них не участвуют в работе; правка цвета требует 6+ файлов.
*Решение:* ввести `internal/gui/theme_tokens.go` — единый источник: `type palette struct { bg, surface, surfaceAlt, text, textSecondary, textDisabled, borderSubtle, borderStrong, primary, primaryFill, onPrimary, success, successFill, warning, warningFill, error, errorFill, selection fyne.ThemeColorName-совместимые константы }`. `ModernTheme` переписывается на таблицы `map[fyne.ThemeColorName]color.Color` для light и dark; все кастомные семантические имена (`ColorNameSurfaceAlt`, `ColorNameBorderStrong`, `ColorNamePortOpen`, …) объявляются рядом и **обязательно** переопределяются в обеих темах.
*Точки правки:* `internal/gui/theme.go`, новый `theme_tokens.go`; `theme_manager.go` — удалить или превратить в тонкую обёртку над `App.applyTheme` (D-01); `results_charts.go:43-68` — `chipBackground/rowBackground/themeColorSuccess/themeColorDisabled` → чтение токенов; `scan_ui.go:87,108`; `ui_helpers.go:240,244,249`; `topology_interactive_map.go:48-77`; `app.go:317-326` (`piePalette` → `palette.Series`).
*Критерии приёмки:* (1) `grep -n "color.RGBA{" internal/gui/*.go` без `_test.go` даёт 0 совпадений, кроме самого `theme_tokens.go`; (2) смена одной константы токена меняет цвет во всех представлениях; (3) `go test ./internal/gui/...` зелёные.
*Риски/тесты:* `theme_test.go:103-133` жёстко проверяет `#F5F5F7`, `#202020`, `#000`, `#FFF` — обновить под новую палитру (§8).

**P0-2. Починить переключатель темы в меню**

*Проблема:* выбор темы не применяется, `Checked` не подсвечивается (F-01).
*Решение:* держать в меню пару `(человеческая подпись, ThemeMode)`; `applyTheme(mode)`+`saveTheme(mode)`; после применения — `a.setupMainMenu()` (перестроить меню с корректным `Checked`) или инкрементально обновить пункты; порядок пунктов зафиксировать срезом, а не `map` (C-11).
*Точки правки:* `internal/gui/ui_helpers.go:126-155`, `theme_selector.go:19-42`.
*Критерии приёмки:* каждый из трёх пунктов меняет реальный цвет фона окна; у активного пункта `Checked == true`; порядок пунктов «Акцент» детерминирован (слайс имён + сортировка).
*Тесты:* юнит-тест на `map[string]ThemeMode` и на то, что `applyTheme(ThemeMode("Светлая"))` — невозможно (типизированный вход), либо табличный тест `подпись → режим`.

**P0-3. Настоящий режим «Системная»**

*Проблема:* `SetTheme(nil)` даёт форсированную встроенную тёмную тему и отключает слежение за ОС (F-02).
*Решение:* тема должна **-resolve-иться по активному варианту в момент запроса**: `ModernTheme.Color(name, variant)` использует переданный `variant`, когда режим = System, и жёсткий `isDark` — когда Light/Dark; для System в `applyTheme` устанавливать `&AppTheme{mode: System}` (не `nil`). Тогда `setupTheme()` при смене системного варианта обновит `variant` → все контролы перекрасятся, а `Settings().Theme()` не будет `nil`.
*Точки правки:* `theme.go:28-33`, `theme_selector.go:20-42`.
*Критерии приёмки:* при `mode=system` и системной светлой теме фон окна светлый; переключение системы на dark (или смена `FYNE_THEME=dark`) перекрашивает окно без перезапуска; `theme.Current()` никогда не возвращает `nil`-путь.
*Тесты:* `NewModernTheme` → параметризовать по `variant`; регрессионный тест «`Color(ColorNameBackground, VariantDark)` != `Color(..., VariantLight)` для System-темы».

**P0-4. Вернуть HiDPI**

*Проблема:* `FYNE_SCALE=1` (F-05) — на 125/150/200% интерфейс мелкий, hit-test смещён (именно этот симптом комментировался как «исправление», но лечит он следствие, а не причину).
*Решение:* удалить `os.Setenv`. Если смещение курсора воспроизводится и на scale ≠ 1 — фиксировать причину отдельно (ресайз/координаты в `topologyGraphBox` с `container.NewWithoutLayout` + фиксированным `Resize(1200×800)`, `init_ui.go:38-39` — самый вероятный источник рассогласования координат мыши и hit-теста). Пользовательский override оставить настройкой `gui.ui.scale` → `FYNE_SCALE` **до** создания приложения, по умолчанию «авто».
*Точки правки:* `internal/gui/app.go:384-398`, `init_ui.go:38-41`.
*Критерии приёмки:* на 150% текст читается без лупы, `Canvas().Scale() > 1`; клик по узлу карты совпадает с подсветкой узла.
*Риски:* проверка регрессии ручным прогоном на 100/125/150% — обязательно зафиксировать в `docs/GUI_SMOKE_CHECKLIST.md`.

**P0-5. Палитра, удовлетворяющая WCAG AA**

*Проблема:* §5.1 (7 провалов в светлой теме, 3 в тёмной).
*Решение:* заменить значения на таблицу §5.2; для статусов ввести пары «текст/fill»; `themeColorSuccess/Disabled` удалить как класс; `ColorNameDisabled` поднять до `#6E6E73`/`#8A8A90`; `ColorNamePlaceHolder` — туда же; hover в светлой теме сделать различимым (≈`#E1ECFA`, ≥1.15:1 + смена фона строки, а не только подложки).
*Точки правки:* `theme.go` (обе функции), `accent_colors.go:18-81` (пресеты: `Hover` пересчитать по `primary`), `results_charts.go:61-68`.
*Критерии приёмки:* скрипт §A на целевых токенах: 0 строк `FAIL` для текстовых пар, 0 `<3.0` для графических; бейджи/чипы различимы на обеих темах.
*Риски:* пресеты акцентов («Green», «Orange», «Red») одновременно становятся и `primary`, и «цветом текста ссылок» — для них нужен автоподбор контрастного `onPrimary` (белый/тёмный по luminance).

**P0-6. Починить сортировку результатов**

*Проблема:* R-02 — выбор в `Select` ничего не меняет.
*Решение:* `a.resultsSortSel = widget.NewSelect(opts, func(v string){ a.resultsSort = v; … })`; значения опций сделать внутренними ключами (`ip|hostname|type|open_ports`) с русскими подписями через словарь, чтобы `prefSortMode` и `loadScanSettings` (`ui_helpers.go:272-276`, ожидающий `"IP"/"HostName"`) совпадали с реальными значениями.
*Критерии приёмки:* смена сортировки меняет порядок строк; после перезапуска сортировка восстанавливается (сейчас `Hostname` ≠ `HostName` → не восстанавливается).

*Проблема:* Ctrl+4/Ctrl+5 (N-02), несуществующие `Ctrl+Shift+I/R` в комментарии (D-05).
*Решение:* либо вернуть вкладки Security/Inventory (см. P1-6), либо убрать шорткаты и перенести их на подрежимы (`Ctrl+Shift+S/I`), приведя `appShortcutSpecs`, F1-диалог и `docs/` к одному списку.
*Критерии приёмки:* каждый зарегистрированный шорткат выполняет действие; F1-список == `appShortcutSpecs` == реальное поведение.

### P1 — скорость и точность основной работы

**P1-1. Live-результаты во время скана (progressive disclosure)**

*Проблема:* R-04/F-09.
*Решение:* в `OnResult`-колбэке сканера добавлять строку в модель и ставить `resultsState = scanning`; рендер — по дебаунсу (уже есть `scheduleResultsRender`), сортировка «как есть» без пересборки порядка на каждый пакет; подпись состояния — `Сканирование… 37/254 хоста · 42 найдено · ETA 00:41`.
*Точки правки:* `results_view_render.go:29-72`, `scan_observer.go`, `controller/scan_controller.go`.
*Критерии приёмки:* строки появляются в процессе; при 254 хостах UI остаётся отзывчивым (< 16 мс на кадр в среднем); кнопка «Стоп» доступна всегда.

**P1-2. Переопределить «прилипающий» заголовок и сортировку по клику**

*Проблема:* R-01, R-03; ограничение `widget.Table` (§5.4).
*Решение:* вынести заголовок в отдельный ряд над таблицей (`container.NewBorder(header, nil, nil, nil, table)`), ширину колонок держать в одном слайсе, синхронизировать горизонтальный скролл с `table.ScrollTo`; по клику на ячейку заголовка — инвертировать направление и рисовать `▲/▼` + `aria`-подпись «сортировка по IP, по убыванию».
*Критерии приёмки:* при вертикальном скролле заголовок виден; клик по «Порты» меняет порядок и индикатор направления.

**P1-3. Моноширинные технические колонки и правило усечения**

*Проблема:* T-04, R-07.
*Решение:* `fyne.TextStyle{Monospace: true}` для IP/MAC/портов/версий (в Fyne есть отдельный monospace-шрифт в `theme.Font`); для колонок с переменной длиной — `Truncation: TextTruncateEllipsis` + полный текст в детали/тултипе; вместо `truncateStr` — у усечение канвы.
*Критерии приёмки:* цифры IP/портов выровнены по разрядам; OS-guess не «ломает» вёрстку колонки.

**P1-4. Состояния портов как семантический компонент**

*Проблема:* R-05, §5.2 таблица состояний.
*Решение:* ввести `buildPortChip(state, port, service, version)` — рамка 1 px `border-strong`, фон `*-fill`, текст `*`, маркер формы (●/◌/—) + текст состояния в детали; чипы — `container.NewGridWrap` (перенос по ширине, что заодно приведёт код в соответствие с `GUI_SMOKE_CHECKLIST.md`, D-06).
*Критерии приёмки:* состояние порта различимо по форме, а не только цвету (WCAG 1.4.1); при 48 чипах нет горизонтального «хвоста» за границу карточки.

**P1-5. Постоянный статус-бар**

*Проблема:* N-07, S-02, S-04.
*Решение:* нижняя панель окна (`container.NewBorder(nil, statusBar, …)` в `init_ui.go:294-300`): слева — статус/тост (с типом `info|success|warning|error` и соответствующим цветом+иконкой), в центре — прогресс (`N/M`, ETA), справа — профиль макета, плотность, `Scale`, время последнего скана. `setStatus*` переписать на модель «сообщение + тип + TTL», не трогая панель настроек.
*Критерии приёмки:* статус-бар виден на всех трёх вкладках; тост ошибки не выглядит как успех; прогресс показывает счётчик, а не только полосу.

**P1-6. Выравнинять навигацию: представление результата — в одном месте**

*Решение (вариант B):* вкладки «Сканирование | Результаты (сегменты) | Инструменты», где топология — представление результатов (модель Zenmap). B — крупная перестройка, отложить за пределы P1.

*Проблема:* S-01, F-11.
*Решение:* компонент `emptyState(icon, title, hint, action)`; тексты: пусто после скана («Хостов не найдено. Проверьте CIDR и firewall-ограничения» + кнопка «Изменить диапазон»), фильтры съели всё («Под фильтры не попал ни один хост» + «Сбросить фильтры»), ошибка скана (текст ошибки + «Повторить» + «Скопировать диагностику»), топология без данных.
*Критерии приёмки:* у каждого из 5+ состояний есть заголовок, объяснение и минимум одно действие; в состоянии «фильтры» кнопка сброса появляется внутри области результатов, а не в панели настроек.

**P1-8. Инвалидация кэшей при смене темы/плотности**

*Проблема:* P-05 (pie-кэш), плюс кэш `hostDetailsCache`/`analyticsCacheView` не учитывает тему.
*Решение:* включить вариант темы и плотность в ключ кэша (`buildPieChartCacheKey` → `theme|density|title|data`); очищать `pieChartCache`/`analyticsCacheView` в `applyTheme`.
*Критерии приёмки:* после смены темы диаграммы перерисовываются на новом фоне без ресайза окна.

**P1-9. Событийный ресайз вместо поллинга**

*Проблема:* P-01, S-06.
*Решение:* пересчитывать профиль по событию изменения размера канвы (обёртка над `Window.SetOnClosed`-подобным хуком недоступна → использовать `Resize`-перехват через собственный контейнер-обёртку с методом `Resize(fyne.Size)`, который и детектирует изменение), тикер оставить только как fallback с 1–2 с; debounce 150–200 мс; при смене профиля — не пересобирать результаты целиком, а менять layout-коэффициенты.
*Критерии приёмки:* при перетаскивании разделителя нет полного мигания области результатов; CPU в простое < 1% (сейчас тикер 300 мс + `DoAndWait`).

## 10. Приложение A — расчёт контраста (как получены числа)

```python
# WCAG 2.1 relative luminance + contrast ratio
def chan(c):
    c = c / 255
    return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

def L(h):
    h = h.lstrip('#')
    r, g, b = (int(h[i:i + 2], 16) for i in (0, 2, 4))
    return 0.2126 * chan(r) + 0.7152 * chan(g) + 0.0722 * chan(b)

def contrast(fg, bg):
    a, b = L(fg), L(bg)
    hi, lo = max(a, b), min(a, b)
    return (hi + 0.05) / (lo + 0.05)

# Пороги: текст >= 4.5 (AA), крупный текст/графика/рамки контролов >= 3.0
# (WCAG 1.4.3 и 1.4.11). Альфа-подложки (selection/hover) сначала композициируются
# с фоном, потом считаются.
```

Пороги, применённые в §5: текст обычный — 4.5:1; текст крупный (≥18 pt / 14 pt bold) и нетекстовые элементы (рамки контролов, иконки, чипы, диаграммы) — 3.0:1; разделители, несущие смысл группировки — 3.0:1; чисто декоративные — без требования (но тогда группа должна различаться другим способом).
