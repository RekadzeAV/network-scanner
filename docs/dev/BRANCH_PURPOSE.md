# Назначение рабочих веток

Обновлено: 2026-11-12.

Модель веток проекта. Документ определяет, **где** ведётся работа и **когда** она
попадает в `main`. Процесс коммитов — [../../CONTRIBUTING.md](../../CONTRIBUTING.md)
(Conventional Commits), план работ — [../ROADMAP.md](../ROADMAP.md).

## Модель веток

| Ветка | Роль | Что сюда коммитится |
|-------|------|---------------------|
| `main` | **Итоговый проект** | Только смерженные завершённые ветки. Прямых коммитов в `main` нет |
| `feature/gui-design` | **Разработка по дизайну** | UI/UX: темы, палитра и токены, компоновка панелей, фильтры, статус-бар/тосты, валидация ввода, результаты/аналитика, топология-карта |
| `feature/v2.3.0-plan-continuation` | **Доработки, правки, новые функции** | Ядро (scanner/network/topology/api), CLI, отчёты, метрики, аудит, безопасность, инфраструктура, документация и планы |

Правило разделения: если правка меняет **только** слой GUI — она в
`feature/gui-design`; если затронута логика приложения, API или CLI — в
`feature/v2.3.0-plan-continuation`. Смешивать потоки в одном коммите нельзя.

## Слияние в `main` — только после завершения работ

`main` — витрина рабочего проекта, поэтому в неё не попадают промежуточные
состояния. Условия мерджа:

1. **Работа завершена** — все пункты задачи/этапа закрыты, незакоммиченных
   изменений в ветке нет.
2. **Локальные гейты зелёные** — `go build ./...`, `go vet ./...`,
   `golangci-lint run ./...`, `go test ./... -short`; для изменений с горутинами
   дополнительно `go test -race ./... -short`.
3. **Документация актуальна** — CHANGELOG и соответствующий план обновлены.
4. **Слияние — merge/PR**, не прямые коммиты; после мерджа ветка не удаляется до
   проверки `main` на CI.

Имена веток проверяются правилами веток в **Rulesets** — параметры описаны в
[RULESETS.md](RULESETS.md).

Пока пункт 1 или 2 не выполнен, изменения остаются в рабочей ветке — даже если
они уже протестированы локально.

## `feature/v2.3.0-plan-continuation` — доработки, правки, новые функции

**Назначение:** продолжение работ по каноническому плану
[../UNIFIED_OPTIMIZED_PLAN_2026-09-15.md](../UNIFIED_OPTIMIZED_PLAN_2026-09-15.md)
(этапы E0–E7) и по открытым пунктам [../ROADMAP.md](../ROADMAP.md).

**Текущий статус:** ветка содержит функционал, который ещё не был слит в `main`
(CLI-команды `metrics`/`schedule`, метрики сканирования `ScanMetrics`,
дополнительные тесты).

## `feature/gui-design` — разработка по дизайну

**Назначение:** UI/UX-работа по Fyne v2.7.1: декомпозиция и компоновка панелей,
фильтры-accordion, пресеты, статус-бар/тосты, валидация ввода, результаты/аналитика.

**Текущий статус:** ветка слита в `main` (merge commit `edc54d8`). Все GUI-изменения
принесены в main и прошли гейты `check-gui.ps1` (5/5).

**Правило:** изменения только GUI-слоя; изменения ядра/CLI/API — через
`feature/v2.3.0-plan-continuation`, чтобы не смешивать потоки работ.

## `main` — итоговый проект

**Назначение:** витрина проекта, готовая к сборке и запуску. Содержит только
завершённые и проверенные изменения из рабочих веток. Прямые коммиты запрещены,
включая «мелкие правки документации» — они идут через рабочую ветку.

Сейчас: `edc54d8` (Merge branch `feature/gui-design` — GUI-аудит).

## Правила

1. Одна ветка = один поток работ (реализация плана ≠ UI-переработка).
2. Локальные гейты и условия мерджа в `main` — см. раздел «Слияние в `main`».
3. Рабочие ветки не ребейзятся после пуша в `origin`; для синхронизации с `main`
   используется `merge main` в рабочую ветку.
