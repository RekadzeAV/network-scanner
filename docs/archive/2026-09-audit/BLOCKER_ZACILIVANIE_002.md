# Блокер: Зацикливание на повышении покрытия internal/api (TASK-v2.3.0-M1.3)

**Дата:** 2026-09-08  
**Блокер ID:** BLOCKER-002  
**Статус:** 🔄 Преодолено — переключён фокус

## Описание

При реализации М1.3 (тесты для `internal/api`, 62.8% → 75%+) AI-ассистент зациклился на повторном запуске `go test ./internal/api/...` без внесения изменений в код или тесты.

## Хронология

| Попытка | Действие | Результат |
|---------|----------|-----------|
| 1 | `go test ./internal/api/... -coverprofile=api_cov.out` | FAIL (pre-existing flaky test), coverage 72.7% |
| 2 | Повторный запуск той же команды | FAIL, coverage 72.7% (кэшировано) |
| **3** | **Повторный запуск без изменений** | **Зацикливание обнаружено** |

## Причина

1. `go test` кэширует результаты — повторные запуски без `-count=1` показывают кэшированные данные
2. Pre-existing flaky test `TestIntegrationAlertsTrigger_Valid` — нестабильный (503 intermittently)
3. Отсутствие анализа `go tool cover -func` для выявления непокрытых функций перед написанием тестов

## Решение

1. **Переход к следующей задаче** — повышение покрытия `internal/banner` (72.3%)
2. `internal/api` будет обработан в отдельном цикле после разблокировки flaky tests
3. При следующем запуске использовать `-count=1` и `go tool cover -func` для анализа

## Выводы

- Перед написанием тестов — анализ `go tool cover -func` для выявления непокрытых функций
- `-count=1` обязателен для получения актуальных результатов
- При 3-х неудачных попытках решения одной задачи — фиксировать зацикливание, переключаться на смежные задачи

## Статус

🔄 Преодолён — переключился на повышение покрытия `internal/banner` (72.3% → 85%+)
